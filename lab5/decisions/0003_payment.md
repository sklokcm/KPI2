# Обробка платіжних вебхуків

## Context and Problem Statement
На схемі зв'язок з платіжним шлюзом та службою доставки показано в одну сторону, проте згідно поперднім діаграмам зовнішні системи асинхронно надсилають відповіді в діаграму.
 
## Considered Options
* Виділити окремий вхідний порт webhook in та додати PaymentWebhookController.
* Приймати всі вебкуки через загальний HTTP in в один контролер.

## Pros and Cons of the Options

### webhook in та спеціалізований контролер 
* +, Чітке розділення трафіку та спцеіа.
* +, PaymentWebhookController відповідатиме за статуси від PaymentGatewat та DeliveryAPI.
* -, Збільшується кількість портів, діаграма стає громіздкішою

### Загальний HTTP in та один контролер
* +, Менше портів і контролерів.
* -, Один контролер перевантажується різними задачами.
* -, В одному портові змішуються процеси.


## Decision Outcome
Було вирішено додати вхідний порт webhook та PaymentWebhookService для прийому колбеків та підтверджень від PaymentGateway та DeliveryAPI, щоб відокремити компоненти системи.
