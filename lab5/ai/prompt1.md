### Що можна виправити або покращити

1. У вихідному описанні було кілька друкарських помилок у назвах секцій і зв'язках
   (`ігтеграції`, `пукнтрирною`, `овсіх`). У діаграмі назви унормовані для читабельності.
2. Діаграму варто вважати логічною, а не фізичною: ім'я *API Gateway* означає шар контролерів,
   але один компонент не розкриває маршрутизацію чи балансування навантаження.
3. Контракт `HTTP/HTTPS API` винесений на межі System і чітко пов'язаний з контролерами.
   Це краще показує вимоги до `Web UI -> API Gateway`, ніж прямі лінії до окремих контролерів.
4. Контракт `SQL` утримується репозиторіями та базою даних через порт `SQLout`.
5. Додано всі найважливіші внутрішні зв'язки `Controller -> Service -> Repository`.
   Зв'язки зображені пунктиром, як у вимогах.
6. Для повної системи не вистачає явно змодельованих компонентів менеджера підтримки,
   адмін-панелі та черги звернень. Їх варто додати окремим виправленням вимог,
   якщо підтримка й адміністрування входять у приймальний обсяг Lab 5.
7. Для уникнення залежностей уверх варто підтримувати лише напрямок
   `UI -> Controllers -> Services -> Repositories -> Database`.
8. Зовнішні інтеграції розміщені поза Backend, але всередині System package.
   Це узгоджує їх із позначенням зовнішніх систем у use-case діаграмі.
9. Сервіси можна уточнити додатковими контрактами для промокодів, замовлень,
   оповіщень і служби доставки; поточна діаграма навмисно показує лише верхньорівневі
   залежності за вихідною специфікацією.
